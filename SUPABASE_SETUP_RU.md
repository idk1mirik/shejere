# Настройка защиты для семейного дерева

Ниже самый простой и безопасный путь для твоего сайта на GitHub Pages.

Что получится после настройки:
- редактировать дерево сможешь только ты через email и пароль администратора;
- само дерево будет храниться в облаке Supabase, а не только в браузере;
- гости по-прежнему смогут смотреть сайт через твой текущий вход на просмотр;
- позже можно будет закрыть и просмотр только для приглашённых людей.

## Шаг 1. Создай проект в Supabase

1. Открой [Supabase](https://supabase.com/) и создай аккаунт.
2. Нажми `New project`.
3. Придумай имя проекта.
4. Выбери регион поближе.
5. Сохрани пароль от базы, который покажет Supabase.
6. Дождись, пока проект полностью создастся.

## Шаг 2. Создай таблицы и правила доступа

1. Внутри проекта открой `SQL Editor`.
2. Создай новый SQL-запрос.
3. Открой файл [supabase-schema.sql](<C:/Users/user/Documents/Codex/2026-04-27/files-mentioned-by-the-user-family/supabase-schema.sql>).
4. Скопируй весь текст из файла.
5. Вставь его в SQL Editor.
6. Нажми `Run`.

## Шаг 3. Создай админ-аккаунт

1. Открой `Authentication`.
2. Перейди в `Users`.
3. Нажми `Add user`.
4. Введи свой email.
5. Введи пароль, который будешь знать только ты.
6. Создай пользователя.

## Шаг 4. Выдай этому пользователю роль admin

1. В `Authentication > Users` открой только что созданного пользователя.
2. Скопируй его `UUID` или `User ID`.
3. Снова открой `SQL Editor`.
4. Выполни такой запрос, заменив `PASTE-USER-ID-HERE` на свой реальный id:

```sql
insert into public.family_tree_roles (user_id, role)
values ('PASTE-USER-ID-HERE', 'admin')
on conflict (user_id) do update set role = excluded.role;
```

## Шаг 5. Возьми URL проекта и публичный anon key

1. Открой `Project Settings`.
2. Зайди в `API`.
3. Скопируй:
   - `Project URL`
   - `anon public key`

Важно:
- `anon key` можно вставлять в сайт, это нормально.
- `service_role key` никогда не вставляй в GitHub Pages и вообще во фронтенд.

## Шаг 6. Заполни конфиг сайта

1. Открой файл [supabase-config.js](<C:/Users/user/Desktop/family tree/supabase-config.js>).
2. Заполни его так:

```js
window.SHEDJERE_SUPABASE = {
    url: "https://YOUR_PROJECT.supabase.co",
    anonKey: "YOUR_PUBLIC_ANON_KEY",
    treeSlug: "main-family-tree",
    adminEmail: "your-email@example.com"
};
```

3. Сохрани файл.

## Шаг 7. Обнови сайт на GitHub Pages

1. Залей изменённые файлы в репозиторий.
2. Подожди, пока GitHub Pages обновится.
3. Открой сайт.
4. Нажми `Войти как админ`.
5. Введи свой email и пароль.

## Что важно понимать

- На GitHub Pages нельзя спрятать секреты внутри фронтенда.
- Поэтому безопасный вариант здесь такой: публичный сайт + Supabase + правила доступа на серверной стороне.
- Сейчас реально защищено именно редактирование.
- Просмотр пока остаётся полуоткрытым: через ссылку и гостевой вход.

## Если потом захочешь закрыть просмотр только для родственников

Следующий этап будет такой:
- убираем публичное чтение из `family_tree_states`;
- создаём viewer-аккаунты для родственников;
- разрешаем чтение только пользователям с ролью `viewer` или `admin`.
